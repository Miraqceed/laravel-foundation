# 上げたファイルの流れ（手本）

このパッケージは、上げたファイルの流れ全体を部品にしない。ストレージ（ローカル・S3）・ウイルスの検査の有無・配り方が、アプリごとに違うため。ここに、守ることと手順を書く。名前・中身の確かめ・位置の情報は、部品を使う（`docs/files.md`）。

## ふつうの上げ方（アプリが受ける）

1. **検証する**：`['required', 'file', 'max:10240', 'mimes:…', 'extensions:…']`（画像は `image`。SVG を通さない）。大きさの上限を必ず書く
2. **名前**：`FileName::forUpload($file->getClientOriginalName())` を、表示と DB の列に入れる
3. **保存のキーは、アプリが作る**（ULID など）。利用者の名前を道に使わない（`../` で外へ出る・同じ名前で上書きされる）
4. **画像は位置の情報を消してから保存する**：`ImageMetadata::strip($mime, $file->get())`。壊れた画像は断る
5. **公開のディスク（`public`）に置かない**。配るときにアプリが権限を確かめる

## 配り方

- 利用者が上げたものは `attachment` で配る（`FileName::disposition($name)`）。`inline` で見せるのは、上の確かめを通した画像・PDF だけ
- `X-Content-Type-Options: nosniff` と、保存したときに確かめた種類の `Content-Type` を付ける（ブラウザに種類を当てさせない）
- 署名つきの URL で配るなら、期限を短くし、同じ見出し（`response-content-disposition`・`response-content-type`）を付けさせる

## 署名つきで直に上げる流れ（ストレージへ直に）

大きなファイルをアプリを通さずに上げるとき（S3 の署名つきの POST など）。アプリの検証を通らないので、次を守る。

1. **頼み**：アプリが、申告の名前・種類・大きさ・SHA-256 を確かめ（許す種類・上限）、行（状態「上げ待ち」）と id を作り、**上げる専用のキー**への短い署名（15分など）を返す。署名の条件に、種類と大きさの上限を入れる
2. **確定**：ブラウザが上げ終えたら、アプリが確定する
   - **行のロックの下で、状態を「上げ待ち」から「確定中」に変える。1回だけ**（並んだ確定は、変えられなかった方が何もせずに戻る。2回目の確定が、確かめた後のバイトを写し直せないように）
   - 上げる専用のキーから、**サーバーだけが書く保存のキー**に写し、**写したほうを確かめる**（大きさ・`FileSignature`・SHA-256）。上げる専用のキーを確かめると、まだ有効な署名で、確かめた後に中身を差し替えられる
   - ストレージの読み書きは、DB のトランザクションの外で（ロックを持ったまま外へ話さない）
   - 確かめを通れば「隔離（検査待ち）」、通らなければ「断った」。上げる専用のキーは消す
   - 確定中のまま止まった行（プロセスが落ちた）は、掃除のジョブが後で「断った」にする
3. **検査**（できるなら）：隔離のものだけを、ウイルスの検査に掛ける
   - 検査の前に、保存のキーの中身が確定のときの SHA-256 と同じかを確かめる
   - 検査が止まっていたら投げ、後でやり直す（隔離のまま。配らない）
   - きれいな画像は、位置の情報を消して**別のキー**に書き、以後そちらを配る
4. **結果を書く**：**行のロックの下で、状態が「隔離」のときだけ**、結果（きれい・感染・失敗）と配るキーを書く。同じ知らせを二重に処理したジョブ（期限切れのリースなど）は、後の方が何もしない
   - 二重に動いたジョブが書いた写しは、その写しが**今配っているキーでないときだけ**消す。配っている写しを消さない
5. **掃除**：消した行・断った行のキーは、別のジョブが後で消す（失敗してもやり直す）。消すのは、状態を条件に入れた更新で印を付けた行だけ

### ウイルスの検査を動かせないとき

共用サーバーでは、ClamAV などを動かせないことが多い。そのときは、

- 受ける種類を絞る（画像・PDF。Office・ZIP・実行ファイルを受けない）
- 画像は位置の情報を消して配る
- いつも `attachment` と `nosniff` で配り、ほかの利用者の画面に `inline` で出さない
