# 知らせを1回だけ送る

名前空間 `Miraqceed\Foundation\Notices`。条件に達したときにこちらから送る知らせ（使った量が上限の80%を超えた・猶予があと3日で終わる・試用が明日終わる）を、鍵ごとに1回だけ送る。送れなければ印を戻して次の確かめで送り直す。呼んだときだけ働く。表は有効にしたときだけ作る。

## いつ使うか・使わないか

使う：

- 定期の確かめ（毎時・毎日の schedule）が条件を見て、達していれば知らせる。確かめは何度も流れるが、知らせは回ごとに1回
- 同じ条件を、画面の操作とバッチの両方が見て知らせる（どちらが先でも1回）

使わない：

- **持っている人が1回だけ使う秘密**：`docs/one-time-codes.md` を使う。こちらは「送る側が1回だけ送る」
- **毎回送る知らせ**（ログインの知らせ・注文の確認）：そのまま送る
- **AI の費用の上限の知らせ**：AI の部品が自分で1回にしている（`docs/ai.md`）

自分で書くと、次の穴を踏む：

- 「送ったか」を読んでから送り、後で印を書く2段の形。同時に流れた2つの確かめが両方送る
- 送る前に印を書き、送れなくても印が残る。知らせが二度と送られない
- 印を書いてからプロセスが止まる（時間切れ・強制終了）。送られないまま残る
- 印をトランザクションの中で書き、巻き戻る。送ったのに印がない（または、送っていないのに印がある）

## 有効にする

```php
// config/foundation.php
'notices' => [
    'enabled' => true,      // 真のときだけ表のマイグレーションを読み込む
    'claim_minutes' => 15,  // 取ったまま送っていない印を、取り直すまでの分
    'keep_days' => 400,     // 印を残す日数（keepUntil を渡さないとき）
],
```

```bash
php artisan migrate
# 表のマイグレーションをアプリに写して使うなら
php artisan vendor:publish --tag=foundation-notice-migrations
```

表（`foundation_notices`）はアプリの既定の接続に置く。

## 送る

```php
use Miraqceed\Foundation\Notices\NoticeResult;
use Miraqceed\Foundation\Notices\OnceNotices;

$result = app(OnceNotices::class)->send(
    "usage-80:{$team->id}:{$period}",
    fn () => Mail::to($team->owner)->send(new UsageWarning($team)),
    keepUntil: $periodEnd->addMonth(),
);
```

| 結果 | 意味 |
|---|---|
| `NoticeResult::Sent` | 送った（渡した関数が返った） |
| `NoticeResult::AlreadySent` | 送らなかった。送った印がある、またはほかの処理が取って送っているところ |
| `NoticeResult::Failed` | 渡した関数が投げた。印を戻した（次の `send()` で送る）。記録に残した。**投げない** |
| `NoticeResult::Deferred` | トランザクションの中で呼んだ。取る・送るは確定の後（下の節） |

- 渡した関数が投げても、`send()` は投げない。記録（`report()`）には鍵と例外の種類の名前だけを入れ、例外の文は入れない（送り先のアドレスが入りうる）
- 関数の中で同じ鍵の `send()` を呼ぶと `AlreadySent`

### 鍵の作り方

- **回を入れる**：同じ知らせを期間ごと・上限ごとに送るなら、鍵にその回を入れる（`usage-80:{id}:{期間}:{上限}`）。回が変われば別の鍵で、また送る。上限を上げたときに送り直したいなら上限の値も入れる
- **個人の情報を入れない**：鍵は表と失敗の記録に残る。メールアドレス・名前ではなく id を使う
- 255字まで（超えると `InvalidArgumentException`）。大文字と小文字は別の鍵

### 送れなかったとき：戻すか、戻さないか

既定では印を戻す。次の確かめが送り直す。知らせの多くは、送られないと困る（上限で止まった・猶予が終わる）。

```php
// 送り先が受け取った後に失敗を返しうる（外の知らせのサービスが時間切れを返す）。二重が困るなら戻さない
$notices->send($key, fn () => $webhook->post($payload), keepOnFailure: true);
```

`keepOnFailure: true` では、送れなくても送ったにする（取り直しの分の後も送らない）。漏れは次の回の知らせで拾う、という知らせに使う。

### 条件が戻ったとき

条件が戻ったら（上限を下回った・支払いが済んで猶予が終わった）、印を消す。次に条件に達したら、また送る。

```php
$notices->forget("grace-ending:{$team->id}");
$notices->has("grace-ending:{$team->id}"); // 印があるか（送った・送っているところ）
```

## 確かめを繰り返し流す

送れなかった印・取ったまま止まった印は、**次の確かめ**が送り直す。だから確かめは、条件が変わったときの1回だけでなく、schedule で繰り返し流す（日に1回でもよい）。

```php
Schedule::command('app:check-usage-notices')->hourly();
```

## 取ったまま止まった印

印を取ってから送り終わる前にプロセスが止まると（時間切れ・強制終了）、送っていない印が残る。取ってから `claim_minutes`（既定 15）を過ぎても送った印がなければ、次の確かめが取り直して送る。

- 呼ぶ側が分を渡せる：`send($key, $fn, claimMinutes: 30)`
- 止まる直前に送れていた場合だけ、二重になる
- 送るのに `claim_minutes` より長く掛かると、ほかの確かめが取り直して二重になる。分は送るのに掛かる時間より十分長くする

## トランザクションの中で呼んだとき

トランザクションの中で `send()` を呼ぶと、取るのも送るのも確定の後に行い、`Deferred` を返す。中では表に書かない（MySQL は一意の索引に入れた錠を確定まで持ち、同じ鍵を確かめるほかの要求がそこで待つ）。

- 巻き戻れば、取らず、送らない
- 確定の後に、ほかの処理が先に取っていれば送らない。`Deferred` は「確定の後に送る」ではなく「確定の後に1回だけ送ることを試みる」。確定の後の結果（送った・ほかが送った・送れなかった）は返らない。送れなければ、外で呼んだときと同じく記録に残し、印を戻す
- 結果を知りたいなら、トランザクションの外で呼ぶ

## キューで送るとき

確かめで印を取り、送るのはジョブにする。取れなければ（`null`）ジョブを出さない。

```php
// 確かめ
if ($claim = $notices->claim("trial-ending:{$team->id}", keepUntil: $trialEnd->addMonth())) {
    SendTrialEndingNotice::dispatch($team->id, $claim);
}

// ジョブ
public function handle(): void
{
    // 送る直前に、まだ印を持つかを確かめる（取った時刻を今に延ばす）
    if (! $this->claim->holds()) {
        return; // キューで待つ間に取り直された。取り直した側が送る
    }

    try {
        Mail::to(...)->send(new TrialEnding(...));
    } catch (Throwable $e) {
        $this->claim->release(); // 印を戻す。次の確かめで送り直す
        throw $e;
    }

    $this->claim->sent();
}
```

- `NoticeClaim` は鍵と token だけを持ち、ジョブに渡せる。`holds()`・`sent()`・`release()` は、その token がまだ印を持ち、送っていないときだけ効く
- **`holds()` を送る直前に呼ぶ**。キューが溜まって、ジョブが `claim_minutes` より長く待つと、次の確かめが印を取り直して新しいジョブを出す。前のジョブは `holds()` が偽になり、送らない
- **取り直しの分は、キューの待ちの長さ＋`retry_after` より長くする**（`claimMinutes:` か `claim_minutes`）。毎分の cron でキューを回すと、溜まったときの待ちが15分を超えうる。短くても送るのは1回のままだが、前のジョブが送らずに終わり、取り直した側のジョブを待つので、送りが遅れる
- ジョブの中で送るのに `claim_minutes` より長く掛かると、二重になりうる（`holds()` が延ばすのは、呼んだ時から `claim_minutes`）
- `claim()` をトランザクションの中で呼ぶと、印はそのトランザクションで書かれる（巻き戻れば取らなかったことになる）。確定までの間、同じ鍵を確かめるほかの要求は待つ。ジョブは `afterCommit()` で出す

## 消す

印は `keep_until` まで残る。`send()`・`claim()` に `keepUntil` を渡さなければ、取ってから `keep_days`（既定 400）日。過ぎた行は `model:prune` で消す。

```php
// routes/console.php
Schedule::command('model:prune', ['--model' => [\Miraqceed\Foundation\Notices\Notice::class]])->daily();
```

- **印が先に消えると、同じ回の知らせをもう一度送る。** `keepUntil` は、その回が終わった後にする（月の回なら月の終わりの後、年の更新の前の知らせなら更新の日の後）
- 既定の400日は、年の回の知らせでも、回が終わる前に印が消えないための長さ
- 鍵には id と回だけを入れるので、残る行に個人の情報は入らない

## 時刻

時刻は UTC で書いて、UTC で比べる。アプリの時間帯（`app.timezone`）が UTC でなくても、取り直しの分と期限はずれない。`keepUntil` に渡した時刻は UTC に直して書く。

## 限界

- 二重になるのは次のときだけ：送り先が受け取った後に失敗を返した（既定の戻すとき）／止まる直前に送れていた／送るのに取り直しの分より長く掛かった
- 送ったことを確かめる手段は、渡した関数が返ったことだけ。メールの不達（後で戻ってくる）は分からない
- 1つの知らせを複数の宛先に送るとき、途中で投げると、送れた宛先にも次の確かめで送り直す（既定の戻すとき）。宛先ごとに鍵を分ける
