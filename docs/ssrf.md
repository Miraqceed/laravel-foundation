# 利用者の URL をサーバーから開く（SSRF）

**このパッケージは、この守りを持ちません。** 別のパッケージ [`cboxdk/laravel-ssrf`](https://github.com/cboxdk/laravel-ssrf)（1.5 以上）を使います。
同じ守りを自前で書くと、下の「自分で書くと踏む穴」を1つずつ追い続けることになるためです。

## いつ使うか

利用者が入れた URL を、アプリのサーバーが自分で開くとき。たとえば Webhook の送り先、画像や記事の取り込み、OAuth の戻り先の確かめ、リンクの見出しの取得。
守らないと、`http://169.254.169.254/`（クラウドの鍵）・`http://127.0.0.1:6379/`（Redis）・`http://10.0.0.5/admin` のような社内のアドレスへ、サーバーが要求を出します。

利用者のブラウザに開かせるだけの URL（画面のリンク・転送）は、サーバーから要求を出さないので、この話ではありません（下の「限界」）。

## 最短の手順

PHP 8.4 以上のアプリで：

```bash
composer require cboxdk/laravel-ssrf:^1.5
composer require guzzlehttp/guzzle:"^7.15.2 || ^8.0.1"   # 下の「Guzzle の版」
```

開くとき：

```php
use Illuminate\Support\Facades\Http;

$response = Http::ssrf()->get($url);   // 確かめたアドレスへつなぎ、転送は追わない
```

保存する前に確かめるとき（検証の規則。名前を引いて、引いたアドレスがすべて公開のアドレスかを見る）：

```php
use Cbox\Ssrf\Rules\PublicUrl;

$request->validate(['webhook_url' => ['required', 'url', new PublicUrl]]);
```

保存するときに確かめても、開くときは `Http::ssrf()` で開きます。保存した後に、名前の向き先が社内のアドレスへ変わることがあるためです。

## Guzzle の版

`guzzlehttp/guzzle` は **7.15.2 以上（8 系なら 8.0.1 以上）** にします。それより前には、Guzzle と確かめる側でホストの読み方が食い違い、確かめをすり抜ける弱点があります（CVE-2026-69246）。
`cboxdk/laravel-ssrf` 1.5 の依存は `^7.8.2` で、直る前の版も許します。版はアプリの側で上げます。

## 自分で書くと踏む穴

- **名前を引いて確かめてから `Http::get($url)` で開くと、DNS の書き換えですり抜けます。** Guzzle（curl）はつなぐときに名前を引き直すので、
  1回目に公開のアドレス、2回目に `127.0.0.1` を返す名前で通ります。確かめたアドレスへそのままつなぐ（curl の `CURLOPT_RESOLVE`）必要があります。
- **転送を追うと、転送の先が社内のアドレスでも開きます。** 1回ごとに確かめ直すか、追わないことにします（`Http::ssrf()` は追いません）。
- **ホストの書き方。** `127.1`・`0x7f.0.0.1`・`0177.0.0.1`・`2130706433` は、curl もブラウザも `127.0.0.1` と読みます。末尾のドット（`localhost.`）、
  パーセントエンコード（`%6cocalhost`）、全角の文字（`１２７.０.０.１`）、日本語のドメイン名（`xn--` の形で引かれる）も同じです。
- **IPv6 の中の IPv4。** `::ffff:127.0.0.1`・6to4（`2002::/16`）・NAT64（`64:ff9b::/96`）・Teredo は、中の IPv4 が社内のアドレスになりえます。
- **名前が複数のアドレスを返すとき**は、すべてを確かめます。1つでも社内のアドレスなら断ります。

`cboxdk/laravel-ssrf` 1.5 はこれらを扱います（2026-11-16 にコードを読んで確かめた）。

## してはいけないこと

- 利用者の URL を `Http::get($url)`・`file_get_contents($url)`・`curl_exec()` で直に開かない。
- `gethostbyname()` などで引いて確かめるだけの守りを自前で書かない（上の DNS の書き換え）。
- `Http::ssrf()` に `->withOptions(['proxy' => …])` を足さない（下の「限界」）。

## 限界

- **プロキシを通すと、つなぐ先の固定が効きません。** `HTTP_PROXY`・`HTTPS_PROXY` を設定した環境では、名前を引くのはプロキシです。
  サーバーの出口のファイアウォール（セキュリティグループ）で、社内のアドレスと `169.254.169.254` を止めるのが本筋で、アプリの守りはそれに重ねるものです。
- **ext-curl がないと、つなぐ先の固定が効きません**（固定は curl の機能）。Laravel の HTTP クライアントは、ext-curl があれば curl を使います。
- **`assertSafeRedirect()`（ブラウザに開かせる URL 向け）は名前を引かず、`127.1`・`0x7f.0.0.1`・`0177.0.0.1` のような短い・8進・16進の書き方を見落とします。**
  サーバーから開く URL の確かめには使わず、`Http::ssrf()`・`PublicUrl`（名前を引く確かめ）を使います。
- **PHP 8.3 のアプリでは使えません**（`cboxdk/laravel-ssrf` は PHP 8.4 以上）。PHP を 8.4 へ上げてから入れます。
- 返ってきた中身（大きさ・形）は守りの外です。読む前に大きさの上限をかけます。
